# Профили TCP, QUIC и UDP — версия 0.4.5

TCP-кандидат `fake_split`: ложный TLS с `badsum ×10`, затем `multisplit` в позициях `1,midsld`, диапазон исходящих пакетов `-n20`. Это один из шести фиксированных TCP-профилей. Исторические результаты прежних параметров не доказывают работу текущего варианта; сохранённый `alt1` не переключается автоматически.

В 0.4.5 исправлен путь QUIC-проверок с самого роутера: отдельный `nfqws2-quic` принимает GSO-пакеты в очереди 214, а только в этом диагностическом процессе отключается несовместимая сборка QUIC Initial. Основной движок очереди 213, TCP/UDP-проверки и сохранённые профили не заменяются. Это исправление проверки, не автоматическое включение QUIC и не доказательство воспроизведения видео.

Это описание новой сборки. Наличие файла или пакета не означает, что обновление установлено на роутер. Развёртывание и изменение маршрутов Podkop — отдельные действия.

## Что выбирать

Одна служба может одновременно обрабатывать разные протоколы:

- **TCP / HTTPS** — обычные HTTPS-соединения. Сохраняется выбранный ранее TCP-профиль, например `alt1`.
- **QUIC** — HTTP/3 поверх UDP/443. Доступны Google QUIC Initial (`quic_google`), штатная заготовка (`quic_zero`) и варианты каждой с изменённой контрольной суммой (`quic_google_badsum`, `quic_zero_badsum`) либо TTL 2 (`quic_google_ttl2`, `quic_zero_ttl2`) только у ложных пакетов.
- **UDP / голос** — распознанные Discord IP discovery и STUN на фиксированных диапазонах UDP 19294–19344 и 50000–50100. `udp_fake2` / `udp_fake6` — нулевая заготовка с разным числом повторов; `udp_protocol_fake2` — отдельные ложные заготовки для каждого протокола; `udp_badsum2` / `udp_ttl2` — варианты нулевой заготовки с badsum / TTL 2; `udp_protocol_badsum2` — протокольные заготовки с badsum. Это не обработчик любого UDP и не универсальный игровой режим.

Это по шесть **вариантов настроек**, не шесть независимых алгоритмов. Все новые варианты экспериментальные. TTL 2 может не достигать фильтра; badsum не гарантирует одинакового поведения на любом сетевом оборудовании. Проверка синтаксиса и запуска Lua не доказывает обход. Фрагментация, изменение длины оригинального UDP и отправка с удалением оригинала не добавлены: их безопасность с текущей маршрутизацией отдельно не подтверждена.

Списки адресов определяют **где** применяется обход. Профили определяют **как** он работает. Выбор профиля не меняет страну внешнего IP и не удаляет правила VPN.

## Обычный сценарий

1. Откройте общую вкладку **Профили**. Сводка показывает сохранённые настройки всех групп; работа службы отображается отдельно.
2. Выберите TCP, QUIC или UDP. Навигация ничего не применяет.
3. В списке **Профиль** выберите **Выключено** либо конкретный профиль. Отдельного переключателя включения нет. Выбор ещё не меняет работающую службу — нужна кнопка **Применить**.
4. Если проверка поддерживается, выберите конкретные ресурсы, запустите её и дождитесь окончания, включая очистку временных правил.
5. Примените выбранную настройку отдельной кнопкой. Успех подтверждается ответом задачи и повторным чтением фактических сохранённых настроек.

Выключение одной группы сохраняет выбранный для неё профиль и не выключает остальные группы. Отключать всю обработку нужно общим **Стоп**, а не выключением последней группы. Применение к остановленной службе не запускает её автоматически. На работающей службе изменение может кратко перезапустить только её собственный обработчик.

Тест выбранного кандидата не назначает победителя и не подменяет сохранённый профиль. Ошибка, устаревший ответ, неизвестное состояние, незавершённая очистка или восстановление не должны разрешать новое применение.

## Как читать результаты

- Успешная проверка TCP означает полную загрузку указанного HTTPS-ресурса с проверкой TLS, содержимого и диагностического прямого маршрута. Проверки изображения YouTube и CSS Discord не доказывают видео или звонки.
- Проверка QUIC использует настоящий HTTP/3 без перехода на TCP. Требуются проверка сертификата, полное тело, ожидаемый хеш и диагностический прямой маршрут. В сборку включён частный `/usr/lib/zapret2-home/curl-http3` 8.23.0 с ngtcp2/nghttp3; системный `/usr/bin/curl` и библиотеки Podkop не заменяются. Оба клиента используют доверенный CA-файл роутера. При отсутствии/повреждении частного клиента проверка остаётся недоступной; TCP-подмена запрещена.
- Ответ STUN считается протокольным результатом только после проверки транзакции, структуры, XOR-MAPPED-ADDRESS и прямого внешнего адреса. Это **не** доказательство звонка Discord.
- Реальная проверка голоса требует работающей авторизованной голосовой сессии. Программа не запрашивает и не сохраняет ваш Discord-токен и не выдумывает проверку по случайному SSRC.
- Молчание сервера, ошибка TLS, HTTP 403/429 или блокировка по региону — разные результаты. Они не доказывают одну общую причину.

## Безопасные значения и совместимость

На новой установке включён только TCP; QUIC и UDP выключены. На обновлении сохраняются существующие настройки, область LAN, списки, автозапуск и намерение запуска. Для старого конфига без новых полей используются те же безопасные значения. Старый интерфейс применения TCP не должен сбрасывать новые группы.

Общие настройки устройств, адресов и списков не дублируются для каждой группы. Исключения VPN, DNAT, локальных и специальных адресов остаются обязательными. Никакие новые правила не должны захватывать VPN-соединение самого роутера.

Проверки используют фиксированные цели, отдельную очередь и ограниченное время; глобальные firewall/VPN/DNS/MTU/offload не перенастраиваются. Локальные браузерные тесты проверяют интерфейс на моделируемом backend, а не реальную авторизованную LuCI-сессию и не обход провайдера.
